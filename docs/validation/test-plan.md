# План тестування (Test Plan) 

**Обсяг:** Тестуємо ключові користувацькі потоки: реєстрацію/авторизацію (FR-001), систему відгуків та модерацію (FR-003, FR-004, FR-008, FR-009, SEC-002), а також перегляд списку відгуків з пагінацією та фільтрацією (US-008). 

**Свідомо НЕ тестуємо на цьому етапі:** алгоритми рекомендацій (US-007), багаторівневі коментарі (US-010), а також US-001 (Watchlist), US-004 (Watched List), US-005 (Фільтрація) та US-009 (Сортування), оскільки цей функціонал ще не імплементовано і він винесений у наступний спринт. Для тестів нереалізованого функціоналу (пошук, JWT-авторизація, рольові перевірки BOLA, бан користувачів) у тест-плані встановлюється статус `[xfail: заплановано]`.

**Критерії виходу:** Усі наявні тести плану зелені в CI (GitHub Actions: раннер `[self-hosted, macOS, ARM64]`), покриття коду бекенду перевіряється через `pytest-cov` із встановленим жорстким порогом `--cov-fail-under=80` (фактичне покриття 99%), відсутні відкриті критичні дефекти безпеки за сканером Bandit.

**Ризики:** Найімовірніше зламається безпека при обробці користувацького тексту (XSS-ін'єкції та спам у відгуках — SEC-002) та швидкодія під час навантаження (PERF-001). Системний тест навантаження (кейс 8) автоматизовано через k6-скрипт `tests/perf/k6-search.js` та винесено в окремий прогін, щоб не сповільнювати швидкий CI.

### Тести поточного спринту (PR #108 та PR #109)

Для забезпечення повної відповідності реалізованого коду тест-плану внесено тести, розроблені в межах PR #108 та PR #109:

#### 1. CRUD-операції та параметризація меж (PR #108, `tests/test_reviews.py`):
- `test_create_review_valid_ratings_boundary` — параметризована перевірка допустимих значень рейтингу `[1, 2, 5, 9, 10]` (201 Created).
- `test_create_review_invalid_ratings_boundary` — параметризована перевірка неприпустимих значень рейтингу `[0, -1, -10, 11, 100, 999]` (422 Validation Error).
- `test_create_review_text_length_boundaries` — перевірка граничних довжин тексту: 9 (422), 10 (201), 200 (201), 5000 (201), 5001 (422).
- `test_get_reviews_min_rating_filter` — параметризована фільтрація за `min_rating` (`[1, 5, 8, 10]`) з інспектуванням виразу SQLAlchemy.
- `test_get_reviews_with_content_filter` та `test_get_reviews_with_user_filter` — фільтрація списку рецензій за контентом та автором.
- `test_get_review_by_id_success` / `test_get_review_by_id_not_found` — отримання рецензії за UUID або 404 помилка.
- `test_update_review_success` / `test_update_review_not_found` / `test_update_review_invalid_data` — часткове оновлення (PATCH).

#### 2. Специфікація та перевірка політик модерації (PR #109, `tests/test_utils.py`):
- `test_policy_clean_text` — пропуск валідного тексту без порушень.
- `test_parameterized_policy_violations` — виявлення спам-посилань (`spam_links`), обсценної лексики (`profanity`), крику (`shouting`) та обфускації (sh1t, f*ck).
- `test_policy_multiple_violations` — комбінація декількох порушень в одному тексті.
- `test_policy_false_positives` — захист від помилкових спрацьовувань (слова "classic", "shift").
- `test_policy_empty_text` — коректна обробка порожнього рядка.
- `test_create_review_policy_violation` та `test_update_review_policy_violation` — інтеграція модерації в роути `POST` та `PATCH` (повернення 400 `POLICY_VIOLATION`).

### 2. Тести з техніки тест-дизайну: Таблиця рішень (Decision Table) (+0,25 бала)

Для бізнес-логіки модерації контенту рецензій (`check_review_policy_violations` та перевірки валідності тексту) побудовано формальну **Таблицю рішень (Decision Table)**. Вона покриває всі комбінації прапорців порушень та довжини тексту:

* **Умови (Conditions):**
  * $C_1$: Текст містить спам-посилання (`https?://`)
  * $C_2$: Текст містить обсценну / ненормативну лексику
  * $C_3$: Текст є криком (>80% великих літер при довжині > 20 символів)
  * $C_4$: Довжина тексту є валідною ($10 \le \text{len} \le 5000$)

* **Дії / Очікуваний результат (Actions / Expected Outcomes):**
  * $A_1$: Схвалено (HTTP 201 Created / список порушень порожній `[]`)
  * $A_2$: Відхилено з 400 Bad Request (`POLICY_VIOLATION`)
  * $A_3$: Відхилено з 422 Unprocessable Entity (`VALIDATION_ERROR`)

| Правило (Rule ID) | $C_1$ (Спам) | $C_2$ (Мат) | $C_3$ (Крик) | $C_4$ (Довжина) | Очікувана дія / порушення | ID зіставленого тесту |
|---|---|---|---|---|---|---|
| **DT-01** | Ні | Ні | Ні | Так | $A_1$: Схвалено (`[]`) | `test_decision_table_content_moderation[DT-01]` |
| **DT-02** | **Так** | Ні | Ні | Так | $A_2$: Помилка 400 (`spam_links`) | `test_decision_table_content_moderation[DT-02]` |
| **DT-03** | Ні | **Так** | Ні | Так | $A_2$: Помилка 400 (`profanity`) | `test_decision_table_content_moderation[DT-03]` |
| **DT-04** | Ні | Ні | **Так** | Так | $A_2$: Помилка 400 (`shouting`) | `test_decision_table_content_moderation[DT-04]` |
| **DT-05** | **Так** | **Так** | Ні | Так | $A_2$: Помилка 400 (`spam_links`, `profanity`) | `test_decision_table_content_moderation[DT-05]` |
| **DT-06** | **Так** | Ні | **Так** | Так | $A_2$: Помилка 400 (`spam_links`, `shouting`) | `test_decision_table_content_moderation[DT-06]` |
| **DT-07** | **Так** | **Так** | **Так** | Так | $A_2$: Помилка 400 (усі 3 порушення) | `test_decision_table_content_moderation[DT-07]` |
| **DT-08** | - | - | - | **Ні** (<10) | $A_3$: Помилка 422 (`VALIDATION_ERROR`) | `test_create_review_text_length_boundaries[9-422]` |

Усі рядки таблиці рішень реалізовано у вигляді параметризованих тестів у `tests/test_utils.py::test_decision_table_content_moderation` та `tests/test_reviews.py`.

### 4. Виконуваний нефункціональний тест (+0,25 бала)

Нефункціональну вимогу **T-008 (NFR PERF-001)** перетворено на виконуваний навантажувальний тест на базі інструменту **k6**.

* **Файл тесту:** `tests/perf/k6-search.js`
* **Встановлені пороги (Thresholds):**
  * `http_req_duration: ['p(95)<500']` (p95 < 500 мс)

* **Команда запуску:**
  ```bash
  k6 run tests/perf/k6-search.js
  ```
