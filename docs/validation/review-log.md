# Підсумок взаємного огляду (Review Log)

**Команда-рецензент:** [Vibecoders (Рецензія на PR #107)](https://github.com/ukma-fin-ssdm-2026/ctrl-alt-defeat/pull/107)

### 3 сильні сторони:
1. Використано ризик-орієнтований підхід із чесним визначенням обсягу тестування та найвразливіших місць (XSS, швидкодія).
2. Зазначені конкретні, перевірні результати для тестів (HTTP-статуси, числові пороги).
3. Зручна та добре читабельна структура таблиці з чітким розподілом типів тестів та власників.

### 2 зони для покращення:
1. Очікувані результати в деяких кейсах суперечили початковим вимогам або були неоднозначними (наприклад, "м'яке" видалення замість повного, відсутність профілю навантаження).
2. Неповнота покриття критичних шляхів (відсутні тести на авторизацію, перевірку Watched List, блокування) та відірваність від реалій CI (відсутність БД у пайплайні).

### Зміни, які ми внесли після огляду:
* **Обсяг та CI:** Додано явний перелік виключених історій (US-001/004/005/009). Зазначено, що CI використовує автоматизований запуск тестів із налаштуванням `--cov-fail-under=80`. Системний тест швидкодії (кейс 8) автоматизовано у k6-скрипті `tests/perf/k6-search.js` та винесено в окремий прогін. Для нереалізованого функціоналу впроваджено статус `[xfail: заплановано]`.
* **Критерії прийняття:** Змінено таблицю — розділено колонку результату на «Передумови / дані» та «Очікуваний результат».
* **Виправлення кейсів:** 
  * Кейс 5 виправлено на остаточне видалення з БД (`DELETE 204 No Content`).
  * У кейсі 7 обрано чітку поведінку для XSS та спаму (запит відхиляється з помилкою 400 `POLICY_VIOLATION`).
  * У кейсі 8 додано точний профіль навантаження (100 VU, 5 хв, p95 < 500 мс).
  * Кейс 7 переприв'язано до релевантної NFR-вимоги валідації вводу (`SEC-002`).
* **Усунення дублювання ID:** Нові тест-кейси отримали унікальні ідентифікатори: `T-035` (Watched List, FR-004), `T-036` (блокування користувача, FR-009), `T-037` (отримання токена, FR-001) та `T-038` (перегляд відгуків, US-008).
