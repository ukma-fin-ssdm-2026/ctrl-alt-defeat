# ADR-003: Хостинг на Render, база даних Neon і поштовий ретранслятор

**Статус:** Прийнято  
**Дата:** 2026-11-24  

## Контекст
* Онлайн-версія потрібна для демонстрацій і перевірки викладачем без витрат на інфраструктуру: усі сервіси мають бути безкоштовними.
* Застосунок уже збирається в один Docker-образ (FastAPI + зібраний React), тому хостинг має запускати контейнер і розгортати кожен коміт у `main` після зеленої перевірки CI.
* ADR-002 вимагає PostgreSQL, а дані користувачів (акаунти, рецензії, коментарі) мають зберігатися довше за місяць.
* Реєстрація (FR-001) і відновлення пароля потребують надсилання листів, а в команди немає власного поштового домену.

## Рішення
1. **Render Web Service** (безкоштовний план, регіон Frankfurt) запускає Docker-образ із `Dockerfile`. Сервісом керує Blueprint `render.yaml`; Render сам розгортає кожен коміт у `main` і перемикає трафік після успішної перевірки `/health/live`. Секрети зберігаються лише в Environment на Render.
2. **Neon Serverless PostgreSQL 16** (Frankfurt) — основна база. Підключення через пул з'єднань Neon (PgBouncer) по TLS (`sslmode=require`); застосунок задає тайм-аути підключення, очікування пулу й запиту (`src/api/db/database.py`).
3. **Google Apps Script → Gmail** — поштовий ретранслятор (`scripts/google-apps-script/mailer.gs`): бекенд надсилає HTTPS-запит зі спільним секретом, скрипт відправляє лист через Gmail.
4. Workflow `keep-alive.yml` опитує `/health/live` кожні 10 хвилин, щоб безкоштовний сервіс не засинав, а `production-deployment.yml` фіксує кожне розгортання в GitHub Deployments.

## Наслідки
* **Плюси:**
  * Нульова вартість, HTTPS і автоматичне розгортання без власних серверів.
  * Сервер і база в одному регіоні (Frankfurt), тож затримка запитів до бази невелика.
  * Neon не видаляє безкоштовну базу через 30 днів, на відміну від безкоштовної PostgreSQL на Render.
  * Листи надсилаються без власного домену і працюють, хоча Render блокує SMTP-порти на безкоштовному плані.
* **Застереження:**
  * Сервер і база належать різним провайдерам, тож з'єднання йде через Інтернет; захист — TLS і облікові дані (див. TB-02 у [моделі загроз](../threat-model.md)).
  * Обмеження частоти запитів зберігаються в пам'яті процесу: це коректно, доки сервіс працює одним екземпляром.
* **Мінуси:**
  * «Холодний старт»: без keep-alive сервіс засинає, а обчислювальний вузол Neon прокидається кілька секунд.
  * Квота листів Gmail обмежена, тож ліміти реєстрацій і листів обов'язкові.

## Розглянуті альтернативи
* **Render PostgreSQL (безкоштовна):** Відхилено. База видаляється через 30 днів, і зареєстровані користувачі й рецензії пропали б.
* **SMTP або Brevo:** SMTP-порти заблоковані на безкоштовному плані Render, а Brevo потребує відправника на власному домені. Обидва транспорти лишилися в коді як варіанти налаштування (`services/email.py`).
* **Власний VPS із Docker Compose:** Відхилено через вартість і ручне адміністрування; `docker-compose.yml` використовується лише для локального production-подібного запуску.
