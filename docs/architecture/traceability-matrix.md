## 2. Сценарії атрибутів якості (Quality Attribute Scenarios)

### Сценарій 1: Продуктивність (Performance)
* **Джерело стимулу (Source):** Одночасно 100 гостей системи (T-008).
* **Стимул (Stimulus):** Користувачі одночасно вводять популярний запит у рядок пошуку (наприклад, "Star Wars").
* **Артефакт (Artifact):** API Gateway (FastAPI) та шар кешування (Redis).
* **Середовище (Environment):** Виробниче середовище під час пікового навантаження (вечірній час).
* **Реакція (Response):** API перевіряє наявність результатів цього запиту в Redis. Знаходить збережений JSON і миттєво віддає його клієнтам, уникаючи 100 важких запитів до PostgreSQL.
* **Міра реакції (Response Measure):** 99% запитів обробляються та повертаються клієнту за час **менше 500 мс** без деградації роботи системи.

### Сценарій 2: Безпека (Security)
* **Джерело стимулу (Source):** Зловмисний або скомпрометований користувач (T-007, T-032).
* **Стимул (Stimulus):** Користувач намагається відправити відгук або коментар (US-002, US-010), що містить шкідливий JavaScript-код (XSS-ін'єкція `<script>alert('hack')</script>`).
* **Артефакт (Artifact):** Модуль валідації в FastAPI (Backend).
* **Середовище (Environment):** Публічний доступ до виробничого середовища через Інтернет.
* **Реакція (Response):** Система (FastAPI + Pydantic) розпізнає небезпечні HTML-теги, відхиляє запит (або санітизує/екранує символи) і не записує шкідливий код у базу даних PostgreSQL.
* **Міра реакції (Response Measure):** 100% небезпечних скриптів заблоковано або екрановано; система повертає HTTP 400 (Bad Request) для зловмисника; дані інших користувачів залишаються в безпеці.

### Сценарій 3: Надійність (Reliability)
* **Джерело стимулу (Source):** Внутрішній збій або мережева помилка.
* **Стимул (Stimulus):** Під час запису нової оцінки та перерахунку загального рейтингу фільму (US-002) відбувається збій з'єднання між FastAPI та PostgreSQL.
* **Артефакт (Artifact):** PostgreSQL (СУБД) та транзакційний модуль FastAPI.
* **Середовище (Environment):** Виробниче середовище за нормального навантаження.
* **Реакція (Response):** Система використовує механізм реляційних транзакцій (Rollback). Оскільки обидві дії (додати оцінку і оновити середній бал) не були завершені, транзакція скасовується.
* **Міра реакції (Response Measure):** Дані залишаються консистентними (немає "завислих" оцінок, що не враховані в рейтингу). Користувач отримує повідомлення "Помилка сервера, спробуйте ще раз" (HTTP 500).
