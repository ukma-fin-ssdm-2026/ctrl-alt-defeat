# API Design

## Огляд архітектури

- **Базова адреса:** `http://localhost:8000/api/v1`
- **Стиль API:** REST
- **Автентифікація:** JWT Bearer-токени (Header `Authorization: Bearer <token>` та HttpOnly Cookie `access_token`)
- **Формат відповіді:** JSON
- **Стратегія версіонування:** версія в шляху URL (`/v1`, `/v2`)

## Модель ресурсів

### Review

`Review` представляє рецензію користувача на фільм або серіал.

| Поле                | Тип       | Опис                                                 |
|---------------------|-----------|------------------------------------------------------|
| `review_id`         | UUID      | Унікальний ідентифікатор рецензії                    |
| `user_id`           | UUID      | Ідентифікатор автора рецензії                        |
| `author_nickname`   | string    | Відображуване ім'я (нікнейм) автора рецензії         |
| `content_id`        | UUID      | Ідентифікатор фільму або серіалу                     |
| `content_title`     | string    | Назва фільму або серіалу                             |
| `rating`            | integer   | Оцінка від 1 до 10                                   |
| `review_text`       | string    | Текст рецензії від 10 до 5000 символів               |
| `contains_spoilers` | boolean   | Ознака наявності спойлерів, за замовчуванням `false` |
| `status`            | enum      | Статус: `published`, `hidden` або `deleted`          |
| `created_at`        | date-time | Дата та час публікації                               |
| `likes`             | integer   | Кількість голосів «Підтримую»                        |
| `dislikes`          | integer   | Кількість голосів «Не підтримую»                     |

### Зв’язки

- **User → Review:** один користувач може мати багато рецензій, кожна
  рецензія належить одному користувачу (`user_id`).
- **Content → Review:** один фільм або серіал може мати багато рецензій,
  кожна рецензія належить одному об’єкту контенту (`content_id`).
- **User → ReviewVote → Review:** користувач має щонайбільше один голос за
  рецензію (`review_votes`, первинний ключ `review_id + user_id`, `value` = 1 або -1).

### Content / Movie (Каталог контенту)

`Content` представляє фільм або серіал у каталозі платформи із синхронізацією метаданих з TMDB.

| Поле             | Тип       | Опис                                                   |
|------------------|-----------|--------------------------------------------------------|
| `id`             | integer   | Числовий ідентифікатор для зворотної сумісності        |
| `content_id`     | UUID      | Унікальний ідентифікатор фільму або серіалу            |
| `title`          | string    | Українська назва контенту                              |
| `title_en`       | string    | Англійська або оригінальна назва                       |
| `category`       | string    | Категорія контенту (`Movie` або `Series`)              |
| `genre`          | string    | Основний жанр                                          |
| `genres`         | array     | Список додаткових жанрових тегів                       |
| `year`           | integer   | Рік випуску                                            |
| `rating`         | float     | Середній рейтинг аудиторії (0.0 – 10.0)                |
| `rotten_rating`  | string    | Рейтинг критиків у відсотках (наприклад, "94%")        |
| `img`            | string    | URL-посилання на постер контенту                       |
| `description`    | string    | Синопсис українською мовою                             |
| `description_en` | string    | Синопсис англійською мовою                             |
| `tmdb_id`        | integer   | Зовнішній ідентифікатор у базі TMDB                    |

Використовуються схеми `ReviewCreate`, `ReviewUpdate`, `ReviewResponse`,
`PaginatedReviewsResponse`, а також `ContentResponse` та `PaginatedContentResponse`.

### User (Користувачі та безпека)

`User` представляє обліковий запис зареєстрованого користувача платформи (FR-001, US-011, SEC-001).

| Поле | Тип | Опис |
|------|-----|------|
| `id` | UUID | Унікальний ідентифікатор користувача (`user_id`) |
| `email` | string | Унікальна електронна пошта користувача |
| `nickname` | string | Відображуване ім'я (нікнейм) |
| `hashed_password` | string | Безпечний хеш пароля bcrypt (SEC-001) |
| `role` | enum | Роль у системі: `user` або `admin` |
| `is_verified` | boolean | Статус підтвердження електронної пошти |
| `verification_token` | string (opt) | Одноразовий токен верифікації email |
| `is_active` | boolean | Прапорець активності облікового запису |
| `created_at` | date-time | Дата та час реєстрації |
| `updated_at` | date-time | Дата та час оновлення профілю |

Схеми запитів/відповідей: `UserRegisterRequest`, `UserLoginRequest`, `UserResponse`, `TokenResponse`, `MessageResponse`.

### WatchedItem (Список переглянутого)

`WatchedItem` представляє запис про переглянутий фільм або серіал у профілі користувача (FR-006, US-004).

| Поле | Тип | Опис |
|------|-----|------|
| `id` | UUID | Унікальний ідентифікатор запису |
| `user_id` | UUID | Ідентифікатор користувача, який переглянув контент |
| `content_id` | UUID | Ідентифікатор переглянутого фільму/серіалу |
| `created_at` | date-time | Дата та час позначення контенту як переглянутого |

Схеми: `WatchedItemCreate`, `WatchedItemResponse`, `WatchedListResponse`, `WatchedStatusResponse`.

### WatchlistItem (Список «До перегляду»)

`WatchlistItem` представляє запис у списку «До перегляду» (Watchlist) авторизованого користувача (FR-005, US-001).

| Поле | Тип | Опис |
|------|-----|------|
| `user_id` | UUID | Ідентифікатор користувача (Primary Key, Foreign Key) |
| `content_id` | UUID | Ідентифікатор контенту в каталозі (Primary Key, Foreign Key) |
| `added_at` | date-time | Дата та час додавання фільму/серіалу до списку |

Схеми: `WatchlistAddRequest`, `WatchlistResponse`.

### Операції API

#### Автентифікація та авторизація (Authentication & Authorization)

| Метод | Endpoint | Опис | Успішна відповідь |
|-------|----------|------|-------------------|
| `POST` | `/api/v1/auth/register` | Реєстрація нового акаунту та генерація токена верифікації (FR-001, US-011) | `201 Created` |
| `GET` | `/api/v1/auth/verify` | Підтвердження адреси пошти за одноразовим токеном | `200 OK` |
| `POST` | `/api/v1/auth/login` | Вхід за email/паролем, повернення JWT Bearer токена та виставлення HttpOnly cookie (T-037) | `200 OK` |
| `GET` | `/api/v1/auth/me` | Отримання профілю поточного авторизованого користувача (`get_current_active_user`) | `200 OK` |
| `POST` | `/api/v1/auth/logout` | Вихід користувача та очищення сесійного токена | `200 OK` |

#### Рецензії (Reviews)

| Метод    | Endpoint                      | Опис                      | Успішна відповідь |
|----------|-------------------------------|---------------------------|-------------------|
| `POST`   | `/api/v1/reviews`             | Створити нову рецензію    | `201 Created`     |
| `GET`    | `/api/v1/reviews`             | Отримати список рецензій  | `200 OK`          |
| `GET`    | `/api/v1/reviews/{review_id}` | Отримати рецензію за ID   | `200 OK`          |
| `PATCH`  | `/api/v1/reviews/{review_id}` | Частково оновити рецензію | `200 OK`          |
| `DELETE` | `/api/v1/reviews/{review_id}` | Видалити рецензію (FR-008, US-006; BOLA: дозволено лише автору або адміністратору — T-017, T-018, T-019). Також підтримується видалення через query-параметр: `DELETE /api/v1/reviews?review_id=...` для захисту від CSRF. | `204 No Content` |

Для `GET /api/v1/reviews` доступна фільтрація за `content_id`, `user_id` та `min_rating`.

**Голоси за рецензії («Підтримую» / «Не підтримую»):**

| Метод | Шлях | Опис | Успішна відповідь |
|-------|------|------|-------------------|
| `PUT` | `/api/v1/reviews/votes` | Тіло `{review_id, value}`: `1` — підтримую, `-1` — не підтримую, `0` — зняти голос. Повертає `likes`, `dislikes`, `my_vote`. Один голос на користувача: повторний виклик з тим самим значенням нічого не додає. | `200 OK` |
| `GET` | `/api/v1/reviews/votes/mine?content_id=...` | Мої голоси за рецензії до фільму (щоб підсвітити обрану кнопку) | `200 OK` |

Помилки: `401` без входу, `403 OWN_REVIEW_VOTE` за власну рецензію, `403 ACCOUNT_BANNED` для забаненого (FR-009), `404 REVIEW_NOT_FOUND`. Голоси видаляються разом із рецензією та з акаунтом.

#### Каталог контенту (Movies & Series Catalog)

| Метод | Endpoint                    | Опис                                      | Успішна відповідь |
|-------|-----------------------------|-------------------------------------------|-------------------|
| `GET` | `/api/v1/movies`            | Отримати список фільмів/серіалів каталогу | `200 OK`          |
| `GET` | `/api/v1/movies/{movie_id}` | Отримати деталі фільму/серіалу за ID      | `200 OK`          |

Для `GET /api/v1/movies` підтримуються query-параметри:
- `search` (рядок): пошук за назвою українською або англійською мовою;
- `category` (рядок): фільтр категорії (`Movie` або `Series`);
- `genre` (рядок): фільтр жанру (наприклад, `Фантастика`, `Драма`);
- `year` (ціле число): фільтр за роком релізу;
- `sort_by` (рядок): критерій сортування (`rating_desc`, `rating_asc`, `year_desc`, `year_asc`, `runtime_desc`, `runtime_asc`);
- `skip` та `limit`: offset-пагінація.

#### Рекомендації (Recommendations)

| Метод | Endpoint                  | Опис                                                       | Успішна відповідь |
|-------|---------------------------|------------------------------------------------------------|-------------------|
| `GET` | `/api/v1/recommendations` | Отримати персоналізовані рекомендації для авторизованого користувача (FR-007) | `200 OK` |

Параметри:
- Користувач автоматично витягується з JWT-токена авторизації (`get_current_active_user`), що запобігає BOLA та несанкціонованому доступу до чужих рекомендацій.
- `limit` (ціле число, за замовчуванням 10): максимальна кількість рекомендованих фільмів у відповіді (від 1 до 100).

#### Список «Переглянуте» (Watched List — FR-006, US-004)

| Метод | Endpoint | Опис | Успішна відповідь |
|-------|----------|------|-------------------|
| `GET` | `/api/v1/users/me/watched` | Отримати список усіх переглянутих користувачем тайтлів з метаданими (T-011) | `200 OK` |
| `POST` | `/api/v1/users/me/watched` | Позначити фільм або серіал як переглянутий (T-011) | `201 Created` / `200 OK` |
| `GET` | `/api/v1/users/me/watched/{content_id}` | Перевірити, чи позначено конкретний тайтл як переглянутий | `200 OK` |
| `DELETE` | `/api/v1/users/me/watched/{content_id}` | Зняти позначку «Переглянуто» з контенту (T-012, T-013). Також підтримується `DELETE /api/v1/users/me/watched?content_id=...` для постійної URL-адреси. | `204 No Content` |

#### Список «До перегляду» (Watchlist — FR-005, US-001)

| Метод | Endpoint | Опис | Успішна відповідь |
|-------|----------|------|-------------------|
| `GET` | `/api/v1/watchlist` | Отримати збережений список фільмів/серіалів «До перегляду» користувача (T-001, T-004) | `200 OK` |
| `POST` | `/api/v1/watchlist` | Додати фільм/серіал до власного списку (T-001, захист від дублікатів 409: T-002) | `201 Created` |
| `DELETE` | `/api/v1/watchlist` | Видалити тайтл зі списку перегляду за query-параметром `content_id` (T-003) | `204 No Content` |

#### Підтвердження пошти (FR-001)

| Метод | Endpoint | Опис | Успішна відповідь |
|-------|----------|------|-------------------|
| `POST` | `/api/v1/auth/register` | Створює акаунт у стані `pending` і надсилає лист із посиланням `<APP_BASE_URL>/verify-email?token=…`. Токен у відповіді не повертається: лише в листі | `201 Created` |
| `GET` | `/api/v1/auth/verify?token=…` | Активує акаунт; посилання одноразове | `200 OK` / `400` |
| `POST` | `/api/v1/auth/resend-verification` | Нове посилання для непідтвердженого акаунта; відповідь однакова для будь-якого email, тож перебором не можна з'ясувати, чи існує акаунт | `202 Accepted` |

Транспорт листів обирається змінними оточення: веб-застосунок Google Apps Script з Gmail-акаунта (`GOOGLE_SCRIPT_URL` + `GOOGLE_SCRIPT_SECRET`, працює без власного домену і там, де заблоковано SMTP), HTTP API Brevo (`BREVO_API_KEY`, потрібен власний домен), SMTP (`SMTP_HOST` …) або, якщо нічого не задано, лише запис посилання в лог сервера. Лист надсилається у фоновій задачі після відповіді.

#### Керування власним акаунтом

| Метод | Endpoint | Опис | Успішна відповідь |
|-------|----------|------|-------------------|
| `POST` | `/api/v1/auth/change-password` | Зміна пароля з підтвердженням поточним (`400 INVALID_PASSWORD` / `SAME_PASSWORD`) | `200 OK` |
| `DELETE` | `/api/v1/auth/me` | Видалення акаунта з підтвердженням паролем у тілі запиту; разом з рецензіями, оцінками, коментарями (і коментарями під своїми рецензіями), списками та історією банів; cookie сесії очищується | `204 No Content` |

Демо-акаунти (`SEED_*`) змінити чи видалити не можна (`403 SEED_ACCOUNT_LOCKED`): на публічному сайті їхній пароль бачать усі. Акаунт адміністратора з профілю не видаляється (`403 ADMIN_ACCOUNT`).

#### Адміністрування: блокування користувачів (FR-009, US-006)

Усі ендпоінти вимагають ролі `admin` (`get_current_admin`): гість отримує `401`, звичайний користувач `403`.

| Метод | Endpoint | Опис | Успішна відповідь |
|-------|----------|------|-------------------|
| `GET` | `/api/v1/admin/users` | Список користувачів з поточним баном; пошук `q` за нікнеймом або email, пагінація `skip`/`limit` (T-036) | `200 OK` |
| `POST` | `/api/v1/admin/bans` | Заблокувати користувача: `user_id`, `ban_type` (`temporary` з `duration_days` 1–365 або `permanent`), `reason` до 500 символів. Новий бан замінює попередній; адміністратора заблокувати не можна (`400`) (T-036) | `201 Created` |
| `DELETE` | `/api/v1/admin/bans` | Зняти бан за query-параметром `user_id`; `404 BAN_NOT_FOUND`, якщо бану немає (T-036) | `200 OK` |
| `DELETE` | `/api/v1/admin/users` | Видалити користувача за query-параметром `user_id` разом з усіма його даними (наприклад, спам-акаунт). Адміністратора, себе й демо-акаунт видалити не можна (`400`) | `204 No Content` |

Наслідки бану: забанений користувач може увійти, а `GET /api/v1/auth/me` повертає поле `ban` (тип, причина, `starts_at`, `ends_at`). Створення та зміна рецензії чи оцінки (`POST`/`PATCH /api/v1/reviews`) і коментування (`POST /api/v1/comments`) повертають `403 ACCOUNT_BANNED` з повідомленням про тип, термін і причину. Watchlist, переглянуте й рекомендації доступні. Тимчасовий бан минає автоматично після `ends_at`.

## Проєктні рішення

### Code-First

У проєкті використовується підхід **Code-First**. OpenAPI-специфікація
генерується з реалізації API. У pre-commit hook імпортується
FastAPI-застосунок з `src.api.main` та викликається
`save_openapi_spec(app)`. У результаті створюється
`openapi-generated.yaml`, який використовує Swagger UI.

`FastAPI code → openapi-generated.yaml → Swagger UI`

### Стратегія пагінації

Для `GET /api/v1/reviews` використовується **offset-based pagination**:

- `skip` — кількість записів, які потрібно пропустити; мінімум `0`, за
  замовчуванням `0`;
- `limit` — максимальна кількість записів у відповіді; від `1` до `100`,
  за замовчуванням `10`.

Приклад: `GET /api/v1/reviews?skip=0&limit=10`

`PaginatedReviewsResponse` містить `items`, `total`, `skip`, `limit` та
`has_more`.

### Обробка помилок

API використовує **єдину структуру відповіді з помилкою —
`ErrorResponse`** для всіх помилок, включно з помилками валідації.

``` json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Validation failed",
    "details": [
      {
        "field": "rating",
        "message": "Input should be less than or equal to 10",
        "provided_value": 11
      }
    ],
    "request_id": "request-id",
    "documentation": "/docs"
  }
}
```

`ErrorPayload` містить `code`, `message`, `details`, `request_id` та
`documentation`. Для помилок валідації інформація про кожне некоректне
поле передається у `details`, тому клієнт отримує однаковий формат
відповіді незалежно від типу помилки.

| Код                        | Значення                        |
|----------------------------|---------------------------------|
| `200 OK`                   | Успішне отримання або оновлення |
| `201 Created`              | Успішне створення рецензії      |
| `204 No Content`           | Успішне видалення рецензії      |
| `400 Bad Request`          | Некоректний запит               |
| `404 Not Found`            | Ресурс не знайдено              |
| `422 Unprocessable Entity` | Помилка валідації               |
