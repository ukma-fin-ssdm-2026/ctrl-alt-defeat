# API Design

## Огляд архітектури

**Movie Platform API** --- REST API для роботи з рецензіями на фільми та
серіали.

Основні характеристики API:

-   версія специфікації --- **OpenAPI 3.1.0**;
-   версія API --- **1.0.0**;
-   базовий шлях --- `/api/v1`;
-   основний ресурс --- `reviews`;
-   формат обміну даними --- JSON.

API має операції для створення, отримання, редагування та видалення
рецензій.

## Модель ресурсів

### Review

`Review` представляє рецензію користувача на фільм або серіал.

  -----------------------------------------------------------------------
  Поле                    Тип                     Опис
  ----------------------- ----------------------- -----------------------
  `review_id`             UUID                    Унікальний
                                                  ідентифікатор рецензії

  `user_id`               UUID                    Ідентифікатор автора
                                                  рецензії

  `content_id`            UUID                    Ідентифікатор фільму
                                                  або серіалу

  `rating`                integer                 Оцінка від 1 до 10

  `review_text`           string                  Текст рецензії від 10
                                                  до 5000 символів

  `contains_spoilers`     boolean                 Ознака наявності
                                                  спойлерів, за
                                                  замовчуванням `false`

  `status`                enum                    Статус рецензії:
                                                  `published`, `hidden`
                                                  або `deleted`

  `created_at`            date-time               Дата та час публікації
  -----------------------------------------------------------------------

Для роботи з ресурсом використовуються такі схеми:

-   `ReviewCreate` --- дані для створення рецензії;
-   `ReviewUpdate` --- дані для часткового оновлення рецензії;
-   `ReviewResponse` --- дані рецензії у відповіді API;
-   `PaginatedReviewsResponse` --- список рецензій разом з інформацією
    про пагінацію.

### Операції API

  --------------------------------------------------------------------------------------
  Метод             Endpoint                        Опис              Успішна відповідь
  ----------------- ------------------------------- ----------------- ------------------
  `POST`            `/api/v1/reviews`               Створити нову     `201 Created`
                                                    рецензію          

  `GET`             `/api/v1/reviews`               Отримати список   `200 OK`
                                                    рецензій          

  `GET`             `/api/v1/reviews/{review_id}`   Отримати рецензію `200 OK`
                                                    за ID             

  `PATCH`           `/api/v1/reviews/{review_id}`   Частково оновити  `200 OK`
                                                    рецензію          

  `DELETE`          `/api/v1/reviews/{review_id}`   Видалити рецензію `204 No Content`
  --------------------------------------------------------------------------------------

Для `GET /api/v1/reviews` доступна необов'язкова фільтрація за
`content_id`.

## Проєктні рішення

### Code-First

У проєкті використовується підхід **Code-First**.

OpenAPI-специфікація генерується з реалізації API. У pre-commit hook
виконується імпорт FastAPI-застосунку з `src.api.main` та виклик:

`save_openapi_spec(app)`

У результаті створюється файл `openapi-generated.yaml`.

Swagger UI використовує саме цей згенерований файл для відображення
документації API.

Таким чином:

`FastAPI code → openapi-generated.yaml → Swagger UI`

Це дозволяє підтримувати специфікацію API синхронізованою з його
реалізацією.

### Стратегія пагінації

Для отримання списку рецензій використовується **offset-based
pagination**.

Endpoint:

`GET /api/v1/reviews`

Параметри:

-   `skip` --- кількість записів, які потрібно пропустити; мінімум `0`,
    значення за замовчуванням `0`;
-   `limit` --- максимальна кількість записів у відповіді; від `1` до
    `100`, значення за замовчуванням `10`.

Приклад:

`GET /api/v1/reviews?skip=0&limit=10`

Відповідь `PaginatedReviewsResponse` містить:

-   `items` --- список рецензій;
-   `total` --- загальну кількість знайдених рецензій;
-   `skip` --- поточний зсув;
-   `limit` --- поточний ліміт;
-   `has_more` --- ознаку наявності наступних записів.

### Обробка помилок

Для помилок API використовується структура `ErrorResponse`, яка містить
об'єкт `ErrorPayload`.

`ErrorPayload` включає:

-   `code` --- машинозчитуваний код помилки;
-   `message` --- текстове повідомлення;
-   `details` --- деталі помилок окремих полів;
-   `request_id` --- ідентифікатор запиту для трасування;
-   `documentation` --- посилання на документацію.

Для помилок валідації використовується `HTTPValidationError`.

У специфікації передбачені такі HTTP-коди:

-   `200 OK` --- успішне отримання або оновлення;
-   `201 Created` --- успішне створення;
-   `204 No Content` --- успішне видалення;
-   `400 Bad Request` --- помилка запиту;
-   `404 Not Found` --- ресурс не знайдено;
-   `422 Unprocessable Entity` --- помилка валідації.
