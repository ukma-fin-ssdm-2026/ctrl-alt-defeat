# Вимоги до системи

## Призначення та межі

**Призначення:** Веб-платформа для кіноманів, що дозволяє користувачам знаходити фільми та серіали, вести облік переглянутого контенту (Watched List), ділитися враженнями через рецензії та отримувати персоналізовані рекомендації на основі контенту, який найбільше сподобався.

**Межі системи:**

* **Входить в обсяг (In-scope):** Реєстрація та авторизація користувачів (з підтвердженням email), каталог контенту, пошук та фільтрація, система 10-бального оцінювання, текстові рецензії, особисті списки "До перегляду" (Watchlist) та історія переглядів (Watched List), генерація рекомендацій, модерація контенту адміністраторами, імпорт метаданих про фільми з публічного API (наприклад, TMDB).

* **Поза межами (Out-of-scope):** Стрімінг або хостинг відеоконтенту, соціальні функції (додавання в друзі, приватні повідомлення, чати), монетизація та платні підписки, розробка мобільних застосунків (iOS/Android).

## Глосарій

* **Watchlist (Список "До перегляду")** – персональний перелік фільмів або серіалів, які користувач зберіг для майбутнього перегляду.

* **Watched List (Список "Переглянуте")** – історія контенту, який користувач вже подивився. Поповнюється вручну користувачем.

* **TMDB API** – зовнішній публічний сервіс (The Movie Database), з якого система імпортує базову інформацію про контент (постери, синопсиси, акторський склад).

* **Гість** – неавторизований відвідувач платформи, який має доступ лише до читання інформації.

* **Користувач** – авторизована особа з власним профілем, яка може взаємодіяти з контентом (оцінювати, коментувати, зберігати).

* **Рекомендаційна система** – алгоритм, який підбирає пропозиції контенту для конкретного користувача на основі його вподобань та контенту, який йому сподобався найбільше.

## Нефункціональні вимоги (NFR)

* **PERF-001 (Performance Efficiency - Продуктивність):** Час формування відповіді сервера для сторінок каталогу та результатів пошуку не повинен перевищувати 500 мс (95-й персентиль) за умови одночасного навантаження в 100 активних користувачів.

* **REL-001 (Reliability - Надійність):** Показник доступності системи (Uptime) повинен становити не менше 99.0% протягом календарного місяця (допускається не більше \~7.3 годин запланованого або незапланованого простою на місяць).

* **SEC-001 (Security - Безпека / Конфіденційність):** Усі паролі користувачів повинні зберігатися в базі даних виключно у захешованому вигляді з використанням алгоритму bcrypt (із застосуванням унікальної "солі" для кожного запису).

* **MAINT-001 (Maintainability - Підтримуваність):** Покриття вихідного коду бекенду модульними тестами (Test Coverage) повинно становити не менше 80%, що має автоматично перевірятися під час кожного запуску CI/CD пайплайну.

* **COMP-001 (Compatibility - Сумісність):** Веб-додаток повинен забезпечувати коректне відображення інтерфейсу та збереження повної функціональності (відсутність критичних візуальних спотворень, працездатність елементів керування) в останніх двох мажорних версіях наступних браузерів: Google Chrome, Apple Safari, Microsoft Edge та Mozilla Firefox на десктопних і мобільних платформах.

## Припущення та обмеження

* **A-001 (Припущення щодо даних):** Передбачається, що зовнішнє API для отримання даних про фільми (наприклад, TMDB API) залишатиметься безкоштовним та матиме достатні ліміти запитів для потреб системи.

* **C-001 (Обмеження стека):** Бекенд має бути реалізований виключно мовою Python (з використанням фреймворків FastAPI, Django або Flask).

* **C-002 (Обмеження БД):** В якості бази даних використовується реляційна СКБД (PostgreSQL для production або SQLite для розробки).

* **C-003 (Обмеження фронтенду):** Клієнтська частина реалізується за допомогою базового стека HTML/CSS/JS або бібліотеки React.

## Ризики та відкриті питання

* **R-001 (Ризик масштабування API):** Можливе перевищення безкоштовних лімітів запитів (Rate Limiting) до API TMDB при різкому зростанні кількості користувачів. *Мітигація:* Реалізація кешування даних про фільми на власному сервері бази даних.

* **R-002 (Спойлери у рецензіях):** Користувачі можуть навмисно або випадково розкривати важливі сюжетні деталі у своїх відгуках, що погіршить досвід інших глядачів. *Мітигація:* Додати можливість авторам позначати свої рецензії чекбоксом "Містить спойлери", щоб такий текст був прихований (розгортався лише за кліком).

* **OQ-001:** Який саме математичний алгоритм буде базовим для рекомендаційної системи першої версії (проста фільтрація за збігом жанрів чи колаборативна фільтрація)?
