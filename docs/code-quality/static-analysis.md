# Звіт зі статичного аналізу та якості коду

## 1. Конфігурація та інструменти
Для підтримки високої якості коду та безпеки в проєкті інтегровано такі інструменти статичного аналізу:
- **Лінтер та автоформатер стилю:** `Ruff` та `Black` (перевірка на відповідність PEP 8).
- **Аналізатор безпеки коду:** `Bandit` (пошук вразливостей у Python-коді).
- **Пошук секретів:** `Gitleaks` (перевірка наявності випадкових API-ключів чи паролів перед комітом).
- **Покриття:** Аналізуються всі Python-файли у директорії `src/` (зокрема `src/api/main.py`). Усі інструменти працюють автоматично через `pre-commit`.

## 2. Результати аналізу безпеки (Bandit)

Під час запуску `bandit -r src/` було виявлено таку потенційну вразливість:

- **Інструмент:** Bandit
- **ID правила:** `B104` (Possible binding to all interfaces)
- **Локація:** `src/api/main.py:283` (рядок з викликом `uvicorn.run(app, host="0.0.0.0", port=3000)`)
- **Опис та ризик:** Bandit попереджає, що прив'язка сервера до IP-адреси `0.0.0.0` (усі доступні інтерфейси) є потенційно небезпечною. Це означає, що сервіс прийматиме з'єднання з будь-якої мережі, до якої підключений хост. Якщо брандмауер (firewall) не налаштований правильно, API може бути випадково виставлене в публічний доступ.
- **Рішення:** **Свідомо прийнятий ризик.**
- **Обґрунтування:** Цей API проєктується для запуску всередині ізольованого Docker-контейнера. У контексті Docker прив'язка до `0.0.0.0` є обов'язковою технічною вимогою, щоб контейнер міг приймати трафік із зовнішнього середовища (від Docker-хоста або reverse-проксі). Безпека доступу гарантуватиметься налаштуваннями портів Docker та мережевими політиками на рівні хост-системи, а не на рівні самого Python-додатка.

## 3. Pre-commit із пошуком секретів
У наш `.pre-commit-config.yaml` інтегровано сканер секретів `Gitleaks`. Під час запуску він перевіряє всі файли на наявність залишених токенів або паролів. Перевірка пройшла успішно, що гарантує відсутність злитих чутливих даних у репозиторії.

## 4. Аудит залежностей (Dependabot)
Ми налаштували GitHub Dependabot (файл `.github/dependabot.yml`) для щотижневого аудиту вразливостей у пакетах `pip` та `npm`. Наразі критичних вразливостей (CVE) у залежностях не виявлено. У разі їх появи Dependabot автоматично створить Pull Request із пропозицією оновлення версії, який команда перевірить та зіллє після Code Review.
