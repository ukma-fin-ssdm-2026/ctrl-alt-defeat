# Звіт про прогрес проєкту (Лабораторна робота 5)

Цей документ фіксує стан архітектури прототипу, готовність компонентів, інструкцію із запуску та статус автоматизованого тестування кодової бази **ctrl-alt-defeat**.

## 1. Поточний стан архітектури

Згідно з вимогами до базової структури коду та за результатами зворотного зв'язку Code Review, монолітний файл API було успішно декомпозовано на логічні модулі:
- **`src/api/db/`**: Містить налаштування підключення до бази даних ([database.py](../../src/api/db/database.py)) з підтримкою пулу з'єднань через SQLAlchemy та ORM-моделі `Review`, `Movie`, `User`, `WatchedItem` ([models.py](../../src/api/db/models.py)).
- **`src/api/schemas/`**: Виділено Pydantic-схеми для рецензій ([review.py](../../src/api/schemas/review.py)), каталогу фільмів ([movie.py](../../src/api/schemas/movie.py)), списку переглянутого ([watched.py](../../src/api/schemas/watched.py)), авторизації та користувачів ([auth.py](../../src/api/schemas/auth.py)) та уніфікованих помилок ([errors.py](../../src/api/schemas/errors.py)).
- **`src/api/routers/`**: Ізольовані обробники маршрутів API, згруповані за ресурсами ([reviews.py](../../src/api/routers/reviews.py), [movies.py](../../src/api/routers/movies.py), [recommendations.py](../../src/api/routers/recommendations.py), [watched.py](../../src/api/routers/watched.py) та [auth.py](../../src/api/routers/auth.py)).
- **`src/api/services/`**: Сервісний шар бізнес-логіки: інтеграція із зовнішніми API ([tmdb.py](../../src/api/services/tmdb.py)) з підтримкою кешованого fallback на 30 тайтлів, алгоритм персоналізованих рекомендацій ([recommendations.py](../../src/api/services/recommendations.py)) та безпека автентифікації/хешування bcrypt/JWT ([auth.py](../../src/api/services/auth.py)).
- **`src/api/main.py`**: Точка входу в застосунок FastAPI, що об'єднує маршрутизатори, глобальні Exception Handlers, CORS-налаштування та автоматичну генерацію документації в рамках події `lifespan`.

## 2. Інструкція із локального запуску прототипу

Для запуску мінімального робочого прототипу API виконайте такі кроки:

### 2.1. Створення віртуального оточення та встановлення залежностей
Залежності проєкту зафіксовані у файлі [requirements.txt](../../requirements.txt):
```bash
# Створення та активація venv
python3 -m venv venv
source venv/bin/activate

# Встановлення зафіксованих бібліотек
pip install -r requirements.txt
```

### 2.2. Запуск сервера API
```bash
uvicorn src.api.main:app --reload --host 127.0.0.1 --port 8000
```
Після успішного старту API доступне за адресою `http://127.0.0.1:8000`:
- Інтерактивна документація Swagger: [http://127.0.0.1:8000/api-docs](http://127.0.0.1:8000/api-docs)
- Альтернативна документація ReDoc: [http://127.0.0.1:8000/redoc](http://127.0.0.1:8000/redoc)

## 3. Готовність компонентів та тестування CRUD

### Компонент: «Управління рецензіями» (Reviews Management)
**Статус:** Повністю реалізовано та протестовано.

Усі 5 базових CRUD-операцій реалізовано під префіксом `/api/v1/reviews`:
- `POST /api/v1/reviews` — створення нової рецензії з валідацією полів (оцінка 1–10, довжина тексту 10–5000 символів).
- `GET /api/v1/reviews` — отримання списку рецензій з offset-пагінацією (`skip`, `limit`, прапорець `has_more`) та фільтрацією за `content_id`, `user_id` та `min_rating`.
- `GET /api/v1/reviews/{review_id}` — отримання рецензії за ідентифікатором UUID4.
- `PATCH /api/v1/reviews/{review_id}` — часткове оновлення оцінки або тексту рецензії.
- `DELETE /api/v1/reviews/{review_id}` — видалення рецензії.

### Модульне тестування CRUD ([tests/test_reviews.py](../../tests/test_reviews.py))
Для верифікації CRUD-операцій створено **15 модульних тестів** з ізоляцією через моки SQLAlchemy-сесій:
1. `test_create_review_success` — успішне створення рецензії (HTTP 201).
2. `test_create_review_edge_case_rating` — граничні значення оцінки (1 та 10).
3. `test_create_review_short_text` — відхилення занадто короткого тексту < 10 символів (HTTP 422).
4. `test_get_reviews_pagination` — перевірка коректності пагінації та розрахунку `has_more`.
5. `test_get_reviews_with_content_filter` — фільтрація списку за `content_id`.
6. `test_get_reviews_with_user_filter` — фільтрація списку за `user_id`.
7. `test_get_reviews_min_rating_filter` — фільтрація рецензій за мінімальною оцінкою.
8. `test_get_reviews_min_rating_validation_error` — відхилення невалідного фільтра оцінки (HTTP 422).
9. `test_get_review_by_id_success` — отримання рецензії за валідним ID (HTTP 200).
10. `test_get_review_by_id_not_found` — обробка запиту неіснуючого ID (HTTP 404 з ErrorResponse).
11. `test_update_review_success` — часткове оновлення існуючої рецензії (HTTP 200).
12. `test_update_review_not_found` — помилка 404 при спробі оновити неіснуючий запис.
13. `test_update_review_invalid_data` — помилка валідації 422 при спробі оновлення на некоректний рейтинг.
14. `test_delete_review_success` — успішне видалення існуючої рецензії (HTTP 204).
15. `test_delete_review_not_found_edge_case` — помилка 404 при спробі видалення неіснуючого ID.

### Компонент: «Каталог контенту та інтеграція TMDB» (Movies & Series Catalog)
**Статус:** Повністю реалізовано та інтегровано з базою даних і фронтендом.

- `GET /api/v1/movies` — фільтрація за категорією (`Movie`/`Series`), жанром, роком релізу, сортування за рейтингом, датою релізу та хронометражем (FR-010), повнотекстовий пошук за назвою (українською та англійською мовами), пагінація (`skip`, `limit`).
- `GET /api/v1/recommendations` — генерація персоналізованих рекомендацій контенту (FR-007) на основі історії високих оцінок та улюблених жанрів користувача.
- `src/api/services/tmdb.py` — автономний клієнт TMDB API з кешуванням та автономним fallback-каталогом на 30 тайтлів (виконання вимоги надійності REL-001 та Graceful Degradation).
- `scripts/seed_movies.py` — скрипт первинного наповнення бази даних даними про фільми та серіали.

### Компонент: «Автентифікація та безпека» (Authentication & Security)
**Статус:** Повністю реалізовано на бекенді та фронтенді з автоматизованим тестуванням (T-037).

- `POST /api/v1/auth/register` — реєстрація користувача з валідацією полів, генерацією захищеного токена верифікації та хешуванням пароля bcrypt (SEC-001).
- `GET /api/v1/auth/verify` — підтвердження поштової скриньки за одноразовим токеном.
- `POST /api/v1/auth/login` — вхід користувача, повернення JWT Bearer токена доступу та виставлення захищеного cookie `access_token` (`HttpOnly`, `SameSite=Lax`) (T-037).
- `GET /api/v1/auth/me` — верифікація сесії поточного користувача через залежність `get_current_active_user`.
- `POST /api/v1/auth/logout` — завершення сеансу та очищення cookie авторизації.
- Фронтенд: повноцінні форми реєстрації та входу, збереження токена, Axios request interceptor з автоматичним підставленням `Authorization: Bearer <token>` і `withCredentials: true`, очищення тимчасового користувача `CURRENT_USER_ID` та інтеграція поточного користувача в рецензії та рекомендації.

### Компонент: «Список «Переглянуте»» (Watched List [FR-006])
**Статус:** Повністю реалізовано на бекенді та фронтенді з автоматизованим тестуванням (T-011, T-012, T-013, US-004).

- `GET /api/v1/users/me/watched` — отримання списку переглянутого контенту поточного користувача з метаданими татуювань (назва, жанр, рік, рейтинг, постери), відсортованого за часом додавання.
- `POST /api/v1/users/me/watched` — позначення фільму/серіалу як переглянутого (ідемпотентна дія, створює новий запис або повертає існуючий).
- `GET /api/v1/users/me/watched/{content_id}` — перевірка статусу перегляду конкретного фільму.
- `DELETE /api/v1/users/me/watched/{content_id}` — видалення контенту зі списку переглянутого (HTTP 204 No Content, або 404 Not Found).
- Фронтенд: інтерактивна кнопка-перемикач «👁️ Позначити як переглянуте» / «✓ Переглянуто» на сторінці фільму ([MovieDetails.jsx](../../frontend/src/pages/MovieDetails.jsx)), окрема вкладка «👁️ Переглянуто» у профілі користувача ([UserProfile.jsx](../../frontend/src/pages/UserProfile.jsx)) з лічильником, сіткою карток, можливістю швидкого видалення зі списку та переходу до фільму.
